# 大学生健康协会管理系统 · 最终设计规范

- 版本:v1.1(含用户确认的三轮变更:五级角色 / 扫码签到 / 活动材料归档,详见第 14 节;凡与前文冲突处以第 14 节为准)
- 日期:2026-10-26
- 说明:本文档由三份候选设计方案合成,是后续开发的唯一实施依据。所有分歧已做出明确决策,见文末附录 A。

---

## 0. 设计原则

1. **极简优先**:每条流程手机上不超过三步、表单字段尽量少、列表一屏看清关键信息;一个学生干部每周花半小时就能维护。
2. **权限全部服务端硬校验**:前端菜单/按钮显隐只是体验优化,不是防线;越权一律 403。
3. **状态尽量推导不入库**:进行中/已结束/缺勤等由时间实时推导,避免定时任务与状态漂移。
4. **数据宁留勿删**:软删与状态机优先,物理删除必须满足严格前置条件并二次确认。
5. **规模适配**:几百名会员、每学期几十场活动、单机/校园局域网——同步 SQLite、部分接口全量返回、无连接池、无缓存层,均为有意取舍。

## 1. 概述与技术栈(锁定,不得更改)

单体全栈小系统:单进程 Express 同时提供 REST API 与前端静态资源,数据落单个 SQLite 文件。

| 项 | 选型 |
|---|---|
| 前端 | Vue 3(组合式 API)+ Vite + Element Plus(中文 locale `zh-cn`)+ ECharts + axios + vue-router |
| 登录态 | **不使用 Pinia/Vuex**,`web/src/store/auth.js` 模块级 `reactive` 变量 + localStorage 持久化 |
| 后端 | Node.js ≥ 22.5(推荐 24 LTS)+ Express(**锁定 ^4**,理由见附录 A-22) |
| 数据库 | Node 内置 `node:sqlite` 的 `DatabaseSync`(同步 API),**禁止** better-sqlite3 / sqlite3 等原生编译模块 |
| 密码 | `node:crypto` 的 `scryptSync`,存储格式见第 5 节 |
| 会话 | JWT(`jsonwebtoken`),HS256,7 天 |
| 后端依赖 | 仅 `express`、`jsonwebtoken`,不引入 cors / multer / cookie-parser 等 |
| 开发模式 | 前端 Vite(5173)代理 `/api` → `http://localhost:3000` |
| 生产模式 | `web` 执行 `npm run build` 后,由 Express `express.static` 托管 `web/dist` + SPA fallback,同端口 3000 |

启动命令约定:

- 开发:终端一 `cd server && npm run dev`(端口 3000);终端二 `cd web && npm run dev`(端口 5173)。
- 生产:`cd web && npm run build`,然后 `cd server && npm start`,局域网内访问 `http://<内网IP>:3000`。
- 首次启动自动建表;`members` 表为空时自动执行种子数据(也可手动 `npm run seed`)。
- `node:sqlite` 在部分 Node 版本会打印实验性警告,可用 `node --no-warnings` 静默,不影响功能。

## 2. 角色定义

系统不设独立用户表,**会员即账号**。角色由 `members.role` 表达:

| role 值 | 中文 | 说明 |
|---|---|---|
| `super_admin` | 超级管理员 | 系统全权,唯一可任命管理层;`dept_id` 可为空 |
| `president` | 会长 | 管理层,权限见第 14.1 节;`dept_id` 可为空 |
| `advisor` | 指导老师 | 管理层,与会长权限完全相同 |
| `minister` | 部长 | 管理本部门会员;发布与管理**自己创建**的活动;必须有 `dept_id` |
| `member` | 普通会员 | 浏览公告、报名活动、签到、查看自己的参与记录 |

> 注:v1.0 下文中的"admin"字样一律读作"管理层(president / advisor / super_admin)",精确映射与例外见第 14.1 节。

会员状态 `members.status`:`pending`(待审核)/ `active`(在册)/ `quit`(离会,含毕业与退出)。
**仅 `active` 可登录**;`pending` 审核通过、`quit` 离会即失去登录能力,业务接口因此无需重复做状态校验。

## 3. 数据库设计

数据文件:`server/data/app.db`。连接初始化(`server/src/db.js`)必须执行:

```js
const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync('server/data/app.db');
db.exec('PRAGMA foreign_keys = ON;');   // node:sqlite 默认不开启外键
db.exec('PRAGMA journal_mode = WAL;');  // 读写并发更稳
db.exec('PRAGMA busy_timeout = 5000;');
```

建表 SQL(`server/src/schema.sql`,与下面逐字一致):

```sql
CREATE TABLE IF NOT EXISTS departments (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT    NOT NULL UNIQUE,             -- 部门名,如 活动部
  description TEXT,                                 -- 一句话简介
  sort        INTEGER NOT NULL DEFAULT 0,           -- 前端展示顺序
  created_at  TEXT    NOT NULL                     -- 'YYYY-MM-DD HH:MM:SS'
);

CREATE TABLE IF NOT EXISTS members (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  student_no    TEXT    NOT NULL UNIQUE,            -- 学号即登录账号
  name          TEXT    NOT NULL,
  password_hash TEXT    NOT NULL,                   -- 'scrypt$N$r$p$salt$hash'
  gender        TEXT    NOT NULL DEFAULT '保密' CHECK (gender IN ('男','女','保密')),
  college       TEXT,                               -- 学院,统计与报备用
  grade         TEXT,                               -- 如 '2025级'
  phone         TEXT,
  dept_id       INTEGER REFERENCES departments(id) ON DELETE SET NULL,  -- NULL=未分配
  role          TEXT    NOT NULL DEFAULT 'member' CHECK (role IN ('super_admin','president','advisor','minister','member')),
  status        TEXT    NOT NULL DEFAULT 'active' CHECK (status IN ('pending','active','quit')),
  joined_at     TEXT,                               -- 入会日期 'YYYY-MM-DD'
  created_at    TEXT    NOT NULL,
  updated_at    TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_members_dept   ON members(dept_id);
CREATE INDEX IF NOT EXISTS idx_members_status ON members(status);

CREATE TABLE IF NOT EXISTS activities (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  title       TEXT    NOT NULL,
  description TEXT,                                 -- 纯文本
  location    TEXT    NOT NULL,
  start_time  TEXT    NOT NULL,                     -- 'YYYY-MM-DD HH:MM'
  end_time    TEXT    NOT NULL,                     -- 'YYYY-MM-DD HH:MM'
  capacity    INTEGER NOT NULL DEFAULT 0 CHECK (capacity >= 0),  -- 0=不限名额
  cancelled   INTEGER NOT NULL DEFAULT 0 CHECK (cancelled IN (0,1)), -- 1=已取消(软标记)
  created_by  INTEGER NOT NULL REFERENCES members(id),  -- 部长权限判据
  created_at  TEXT    NOT NULL,
  updated_at  TEXT    NOT NULL,
  CHECK (end_time > start_time)
);
CREATE INDEX IF NOT EXISTS idx_activities_start ON activities(start_time);

CREATE TABLE IF NOT EXISTS activity_signups (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  activity_id   INTEGER NOT NULL REFERENCES activities(id) ON DELETE CASCADE,
  member_id     INTEGER NOT NULL REFERENCES members(id) ON DELETE CASCADE,
  status        TEXT    NOT NULL DEFAULT 'registered'
                CHECK (status IN ('registered','checked_in','cancelled')),
  registered_at TEXT    NOT NULL,                   -- 'YYYY-MM-DD HH:MM:SS'
  checkin_at    TEXT,                               -- 签到时刻,NULL=未签到
  checkin_by    INTEGER REFERENCES members(id),     -- NULL=本人签,非空=补签操作者id
  updated_at    TEXT    NOT NULL
);
-- 部分唯一索引:防重复报名;允许“取消后重新报名”(取消行不占索引)
CREATE UNIQUE INDEX IF NOT EXISTS ux_signup_active
  ON activity_signups(activity_id, member_id) WHERE status != 'cancelled';
CREATE INDEX IF NOT EXISTS idx_signup_member ON activity_signups(member_id);

CREATE TABLE IF NOT EXISTS announcements (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  title           TEXT    NOT NULL,
  content         TEXT    NOT NULL,                 -- 纯文本,前端 pre-wrap 展示
  pinned          INTEGER NOT NULL DEFAULT 0 CHECK (pinned IN (0,1)),
  require_confirm INTEGER NOT NULL DEFAULT 0 CHECK (require_confirm IN (0,1)),  -- 1=需点“我已知晓”
  published_by    INTEGER NOT NULL REFERENCES members(id),
  created_at      TEXT    NOT NULL,
  updated_at      TEXT    NOT NULL,
  deleted_at      TEXT                                -- 非空=已软删除,列表不再可见
);

CREATE TABLE IF NOT EXISTS announcement_reads (
  announcement_id INTEGER NOT NULL REFERENCES announcements(id) ON DELETE CASCADE,
  member_id       INTEGER NOT NULL REFERENCES members(id) ON DELETE CASCADE,
  read_at         TEXT    NOT NULL,
  PRIMARY KEY (announcement_id, member_id)
);
```

设计要点:

- 报名、签到、取消、补签全部在 `activity_signups` 一张表内流转;**不设独立 checkins 表,不设 absent 状态**——缺勤 = 活动已结束且 `status='registered'`,由查询实时推导。
- 容量、出勤统计只数 `status IN ('registered','checked_in')`;已取消的报名(`cancelled`)不占名额。
- 活动不存 `draft`/`published` 状态字段:报名中 / 进行中(start ≤ now ≤ end)/ 已结束(now > end)由时间与当前时刻实时推导;`cancelled=1` 优先于一切状态。
- 事务辅助:所有"读后写"的并发点(报名、自动补报名、补签)统一走 `withTransaction(fn)`(`BEGIN IMMEDIATE` → fn → `COMMIT`,异常 `ROLLBACK`),防止并发抢名额超员。
- 删除部门前校验无 `active` 会员,否则 409;`ON DELETE SET NULL` 保证误删部门时会员资料不丢。

## 4. 统一约定

### 4.1 响应包格式

所有 JSON 接口统一信封:

```jsonc
// 成功
{ "code": 0, "message": "ok", "data": { ... } }
// 失败
{ "code": 409, "message": "活动名额已满", "error": "CAPACITY_FULL" }
```

- `code=0` 表示成功;失败时 `code` 与 HTTP 状态码**镜像**(axios 拦截器按 HTTP 状态分流即可)。
- `message` 恒为中文提示,前端直接展示;`error` 为机器可读枚举,仅失败时出现。
- **例外**:CSV 导出接口成功时直接返回 `text/csv` 文件流(带 UTF-8 BOM,`Content-Disposition: attachment; filename*=UTF-8''<encodeURIComponent(文件名)>`),失败时仍走信封。

### 4.2 错误码

| HTTP / code | error 枚举(示例) | 场景 |
|---|---|---|
| 400 | `VALIDATION` / `BAD_CODE` | 参数缺失或非法、签到码错误 |
| 401 | `UNAUTHORIZED` | 未登录、token 过期或无效、学号或密码错误 |
| 403 | `FORBIDDEN` / `ACCOUNT_PENDING` / `ACCOUNT_QUIT` | 越权、待审核账号登录、离会账号登录 |
| 404 | `NOT_FOUND` | 资源不存在 |
| 409 | `CAPACITY_FULL` / `DUPLICATE` / `STATE_CONFLICT` / `CONFLICT_DEPT_HAS_MEMBERS` / `CONFLICT_HAS_SIGNUPS` | 名额满、重复报名、状态冲突、部门仍有会员、活动仍有报名不可删 |
| 500 | `INTERNAL` | 服务器异常(不向客户端暴露细节) |

部长越权的 403 信息统一为"无权限执行该操作",不区分"不存在"与"无权"。

### 4.3 时间存储格式

- 全部存**服务器本地时间字符串**(单校区部署,无时区问题),字典序即时间序,SQL 可直接字符串比较。
- 活动起止时间:`'YYYY-MM-DD HH:MM'`(分钟精度,与 Element Plus 日期时间选择器格式一致)。
- 其余审计字段(`created_at`、`registered_at`、`checkin_at`、`read_at` 等):`'YYYY-MM-DD HH:MM:SS'`。
- 时间格式化/解析/学期起点计算全部集中在 `server/src/util/time.js` 与 `web/src/utils/format.js`,便于将来迁移。

### 4.4 分页

- 统一参数:`?page=1&pageSize=20`(pageSize 上限 100);筛选关键词统一 `q`,部门筛选 `dept_id`,状态筛选 `status`。
- 分页响应 `data`:`{ items, total, page, pageSize }`。
- **适用范围**:`GET /api/members`、`GET /api/announcements` 分页(随年份增长);活动列表、报名/签到名单、部门列表全量返回(量小,前端直接渲染,CSV 导出也需要全量)。

### 4.5 鉴权头

除"公开"接口外一律要求 `Authorization: Bearer <token>`;token 失效返回 401。

## 5. 认证与会话约定

### 5.1 密码存储(scrypt)

- 算法:`crypto.scryptSync(password, salt, 64, { N: 16384, r: 8, p: 1 })`;盐为 16 字节随机数 hex。
- 存储格式:`scrypt$16384$8$1$<saltHex>$<hashHex>`。
- 校验:按存储串拆参重算,`crypto.timingSafeEqual` 比较。
- 初始密码与管理员重置后的密码统一为 **`123456`**。

### 5.2 JWT

- 算法 HS256,有效期 **7 天**(`expiresIn: '7d'`)。
- 载荷字段:`{ uid: members.id, role: 'super_admin'|'president'|'advisor'|'minister'|'member', deptId: members.dept_id }`。**不含**任何来自请求参数的身份信息,后续一切权限判定只读 `req.user`(中间件解析后挂载 `{ uid, role, deptId }`)。
- 签名密钥:环境变量 `JWT_SECRET`;未设置则首次启动随机生成并写入 `server/data/secret.key`,之后复用(重启不失效)。
- 吊销缓解:鉴权中间件(`requireAuth`)**每次请求回查 `members.status`**,非 `active` 即拒绝——停用/离会立即生效,弥补 JWT 无法主动失效;单表主键查询,量级完全可承受。

### 5.3 首次部署创建管理员账号

- `npm run seed`(以及服务端首次启动检测 `members` 空表时自动执行)创建种子账号:**学号 `20240001`,密码 `123456`,角色 `super_admin`(超级管理员),姓名"陈明"**;同时创建会长(20240002 王浩 president)、指导老师(20240003 林芳 advisor),完整清单见第 11、14.5 节。
- 登录页展示演示账号提示;README 与登录页均注明"演示账号,请登录后立即在『我的』页修改密码"(不做强制改密,记为取舍)。
- 如需自定义初始管理员:修改 `server/src/seed.js` 后删除 `server/data/app.db` 重新启动即可。

## 6. REST API 清单

路径前缀 `/api`。"角色"列中:**登录** = 任意 `active` 用户;**部长(自建)** = 部长且 `activities.created_by = 自己`;**部长(本部门)** = 部长且目标会员 `dept_id` = 自己部门。所有写操作入参在服务端做白名单校验,部长永远不能传 `role` / `dept_id` 修改会员归属。

### 6.1 认证 `routes/auth.js`

| 方法 | 路径 | 用途 | 请求 | 响应 data 要点 | 角色 |
|---|---|---|---|---|---|
| POST | /auth/register | 自荐注册 | `{student_no*, name*, password*, dept_id*(意向部门), phone?, college?, grade?}` | `{}`;学号重复 409 `DUPLICATE` | 公开 |
| POST | /auth/login | 登录 | `{student_no*, password*}` | `{token, member:{id, student_no, name, role, dept_id, dept_name}}`;pending→403,quit→403 | 公开 |
| GET | /auth/me | 当前用户 + 首页小卡 | — | `{member:{...含 dept_name}, unread_count(未读公告数), my_stats:{signup_count, checkin_count}}`(统计为本学期) | 登录 |
| PUT | /auth/me | 改本人资料 | `{phone?, college?, grade?, gender?}`(学号/姓名/部门/角色不可改) | `{member}` | 登录 |
| PUT | /auth/password | 改本人密码 | `{old_password*, new_password*}`(新密码 ≥6 位) | `{}`;旧密码错 400 | 登录 |

### 6.2 部门 `routes/departments.js`

| 方法 | 路径 | 用途 | 请求 | 响应 data 要点 | 角色 |
|---|---|---|---|---|---|
| GET | /departments | 部门列表(注册页需要,故公开) | — | `[{id, name, description, sort, member_count(active 人数)}]` | 公开 |
| POST | /departments | 新建部门 | `{name*, description?, sort?}` | `{department}` | admin |
| PUT | /departments/:id | 编辑部门 | `{name?, description?, sort?}` | `{department}` | admin |
| DELETE | /departments/:id | 删除部门 | — | `{}`;仍有 active 会员→409 `CONFLICT_DEPT_HAS_MEMBERS` | admin |

### 6.3 会员 `routes/members.js`

| 方法 | 路径 | 用途 | 请求 | 响应 data 要点 | 角色 |
|---|---|---|---|---|---|
| GET | /members | 会员列表 | `?q&dept_id&status&page&pageSize`;**部长由服务端强制 `dept_id=本部门`** | `{items:[{id, student_no, name, gender, college, grade, phone, dept_id, dept_name, role, status, joined_at}], total, page, pageSize}` | admin、minister |
| POST | /members | 干部代录会员 | `{student_no*, name*, dept_id?, role?(仅admin), phone?, college?, grade?, gender?}`;初始密码 123456;部长强制 `dept_id=本部门、role='member'`,状态 active | `{member}`;学号重复 409 | admin、minister |
| PUT | /members/:id | 编辑会员 | 可传字段见 9.5 节;admin 全字段(含 `dept_id/role/status`);部长仅本部门 `role='member'` 者的 `phone/college/grade/gender`,且 `status` 只允许传 `'quit'` | `{member}` | admin、minister |
| PUT | /members/:id/review | 审核注册 | `{action*:'approve'\|'reject', dept_id?(仅admin,重指部门)}`;approve→status=active、joined_at=今天;reject→物理删除该 pending 记录 | `{}`;部长只能审核意向部门=本部门的待审者 | admin、minister |
| DELETE | /members/:id | 物理删除会员 | — | `{}`;仅允许 `status='pending'` 或无任何报名/回执记录者,否则 409(离会走状态修改) | admin |
| PUT | /members/:id/password | 重置密码为 123456 | — | `{}` | admin |
| POST | /members/import | CSV 批量导入 | `[{"student_no","name","college","grade","phone","dept_name"}...]`(前端已解析为 JSON 数组) | `{inserted, skipped:[{student_no, reason}]}`;事务内逐行校验,重复学号/部门不存在则跳过 | admin |
| GET | /members/export | 导出会员名册 CSV | 同 GET /members 的筛选参数 | `text/csv`:学号,姓名,性别,学院,年级,手机,部门,角色,状态,入会日期;部长导出内容限本部门 | admin、minister |

### 6.4 活动 `routes/activities.js`

活动派生状态(响应中的 `state` 字段):`cancelled=1 → 'cancelled'`;`now < start_time → 'upcoming'`;`start_time ≤ now ≤ end_time → 'ongoing'`;`now > end_time → 'ended'`。

| 方法 | 路径 | 用途 | 请求 | 响应 data 要点 | 角色 |
|---|---|---|---|---|---|
| GET | /activities | 活动列表(全量) | `?state=upcoming\|ongoing\|ended\|cancelled&q`;`my_status` 为本人状态 | `[{id, title, location, start_time, end_time, capacity, cancelled, state, created_by, created_by_name, signup_count, my_status:'none'\|'registered'\|'checked_in'}]` | 登录 |
| GET | /activities/:id | 活动详情 | — | 上项字段 + `description` + `can_manage`(服务端算好:admin 或创建部长) | 登录 |
| POST | /activities | 发布活动 | `{title*, location*, start_time*, end_time*, capacity*, description?}`;创建即"已发布" | `{activity}`;`end_time>start_time` 否则 400 | admin、minister |
| PUT | /activities/:id | 编辑活动 | 同上;`capacity` 不得低于当前有效报名数,否则 409 `STATE_CONFLICT` | `{activity}`;admin 任意时刻可改;部长(自建)仅 `now < start_time` 可改 | admin、minister(自建) |
| POST | /activities/:id/cancel | 取消活动 | — | `{}`;置 `cancelled=1`,报名记录保留;已结束(now>end)不可取消;已取消再取消 409 | admin、minister(自建) |
| DELETE | /activities/:id | 物理删除活动 | — | `{}`;仅当**零报名记录**(任意状态),否则 409 `CONFLICT_HAS_SIGNUPS` 提示改用取消;级联删报名 | admin |
| POST | /activities/:id/signup | 报名(自报/代报) | 自报 `{}`;代报 `{member_id}`(admin 任意 active 会员,部长限本部门,传自己 id 等价自报) | `{signup}`;完整校验规则见 9.3 | 登录(代报:admin、minister(本部门)) |

## 9. 关键流程与边界规则

### 9.1 注册与审核(纳新)

1. 新会员在 `/login` 注册页签提交:学号、姓名、意向部门、密码等 → 落库 `status='pending'`、`role='member'`、`dept_id=意向部门`。
2. pending **不可登录**(登录接口对 pending 返回 403 `ACCOUNT_PENDING`)。
3. 干部在"会员管理 → 待审核"筛选中处理:**通过**(`action='approve'`)→ `status='active'`、`joined_at=今天`;部长只能通过意向部门=本部门的申请,且部门锁定为本部门;admin 可在通过时重新指定部门。**拒绝**(`action='reject'`)→ 物理删除该 pending 记录(尚无任何业务数据,删除安全)。
4. 也可不经注册,由 admin/部长在会员页直接**代录**(现场纳新场景),初始密码 123456,当场可登录报名。

### 9.2 登录与会话

输入学号密码 → scrypt 校验 → 校验 `status='active'` → 签发 7 天 JWT → 前端 `store/auth.js` 模块级 reactive 保存 token+user 并同步 localStorage;axios 请求拦截器统一加 `Authorization` 头,响应拦截器统一 ElMessage 弹出 `message`、401 时清登录态跳 `/login`;路由守卫白名单 `/login`。

### 9.3 报名规则(精确边界)

前置:活动未取消(`cancelled=0`)。有效报名 = `status IN ('registered','checked_in')` 的记录数;`capacity=0` 表示不限。

| 场景 | 行为 |
|---|---|
| 正常报名 | `BEGIN IMMEDIATE` 事务内:校验 → 计数容量 → 插入 `status='registered'` → COMMIT。容量校验与写入同事务,防并发超员 |
| 重复报名(已有 registered/checked_in 记录) | 409 `DUPLICATE`"请勿重复报名"(用户误操作,明确报错) |
| 容量满(有效报名 ≥ capacity,capacity>0) | 409 `CAPACITY_FULL`"名额已满" |
| 活动已开始(`now ≥ start_time`,即报名截止后) | 409 `STATE_CONFLICT`"报名已截止(活动已开始)" |
| 活动已取消 | 409 `STATE_CONFLICT`"活动已取消,无法报名" |
| 之前取消过(存在 cancelled 行) | 允许重新报名:插入新行(部分唯一索引不拦截),旧行保留作历史 |
| 代报名 | admin 可代任意 active 会员;部长限**本部门**会员;普通会员只能报自己。被代者必须 active |
| 取消报名 | 仅 `now < start_time`;取消 = 当前行置 `cancelled`(不物理删),释放名额。已签到者不可取消(409,提示先撤销签到);无有效报名时取消 409 `STATE_CONFLICT`;代取消权限同代报名 |
| pending/quit 会员报名 | 不可能登录,服务端仍以 403 兜底 |

### 9.4 签到方案:6 位旋转签到码(选定理由见附录 A-4)

**生成算法**(服务端无状态、不落库、无开关字段):

```js
// window = Math.floor(unixSeconds / 60)    // 60 秒一片(v1.1:配合扫码,截图暴露窗 ≤2 分钟)
// code(activityId, window) = HMAC-SHA256(JWT_SECRET, `checkin:${activityId}:${window}`)
//   → hex 摘要 → parseInt(hex.slice(0,8), 16) % 1000000 → 补零到 6 位
// 校验:提交码 === code(当前窗) 或 code(上一窗)   // 容忍时钟偏差
// expires_in = 60 - (unixSeconds % 60)
```

**自助签到流程**:干部打开活动详情 → 管理区显示当前 6 位码与剩余秒数(30 秒轮询刷新)→ 点"全屏大字"投屏/展示 → 会员在详情页输入 6 位码提交 → 服务端校验通过 → `activity_signups` 行置 `checked_in` 并记 `checkin_at`。

**边界规则**:

| 场景 | 行为 |
|---|---|
| 签到时间窗 | 自助签到仅允许 `start_time − 30分钟 ≤ now ≤ end_time`;窗外 409 `STATE_CONFLICT`("签到未开始"/"签到已结束") |
| 码错误 | 400 `BAD_CODE`"签到码不正确"(仅比对当前与上一窗) |
| 重复签到(已 checked_in) | **幂等成功**,返回当前状态与"已签到"提示——现场网络重试友好,不重复写记录 |
| 未报名者输码签到 | 自动补报名(走同一容量事务:容量满则 409 `CAPACITY_FULL`)+ 置 checked_in,一次操作完成;若有 cancelled 旧行则插入新行 |
| 活动已取消 | 409 |
| 活动列表/详情展示 | `my_status` 实时反映,按钮随窗口与状态显隐 |

**干部补签与撤销**:`manual-checkin`(admin 任意会员、部长限本部门会员)在 `start_time − 30分钟` 之后**无上限时限**(含活动结束后补录,服务散场后发现漏签的修正场景),写 `checkin_by=操作者id` 留痕;`DELETE /checkin` 撤销误签(`checked_in→registered`,清空 `checkin_at/checkin_by`)。补签目标未报名时同样先补报名(容量校验)。补签不需要也不校验签到码。

**签到码安全性说明**:5 分钟轮换使截图转发到群里的码最长 10 分钟失效;纯数字码零硬件、零摄像头权限、零外网依赖;残余风险(在场代输、10 分钟内转发)靠"现场口播勿发群"提示与补签留痕事后核对兜底,不做动态二维码/定位/人脸。

### 9.5 部长权限边界(全部服务端硬落实)

**三类防线**:

1. **中间件**:`requireAuth`(验签 + 回查 status)→ `requireRole('admin')` / 业务内联角色判断;身份只来自 JWT,绝不信任 body/query 传入的 deptId/role/memberId 归属。
2. **资源归属断言**:部长对活动的编辑/取消/名单/导出/签到码/撤销签到等,服务端先比对 `activities.created_by = req.user.uid`,否则 403。
3. **数据范围断言**:部长对会员的一切读写,SQL 强制绑定 `dept_id = req.user.deptId`;且目标 `role` 必须为 `'member'`(不能动本部门其他部长/会长)。越权一律 403"无权限执行该操作"。

**字段级限制**(PUT /api/members/:id):

| 字段 | admin | minister |
|---|---|---|
| phone / college / grade / gender | ✅ | ✅(限本部门 member) |
| dept_id(调动部门) | ✅ | ❌ |
| role | ✅ | ❌ |
| status | ✅(pending/active/quit 任意) | 仅可传 `'quit'`(标记离会);不能审核激活、不能恢复 |

**部长代理权**(直接回答"部长能否替本部门成员操作"):**能,但仅限本部门会员**——代报名、代取消、补签、撤销签到均可代本部门成员执行,且不限活动是哪位干部创建的(边界在"会员归属"而非"活动归属");活动管理权则严格限自建。

### 9.6 取消与删除策略

- **会员**:不提供日常删除。离会 = `status='quit'`,历史报名/签到全部保留。物理删除仅 admin,且仅限 pending(审核拒绝)或无任何报名/回执记录的误录入。
- **活动**:发布后不可物理删(除非零报名,仅 admin);取消 = `cancelled=1` 软标记,报名记录保留供追溯,已取消活动在"已取消"页签展示。
- **公告**:软删(`deleted_at`),列表不可见,表内可恢复。
- **报名行**:永不物理删除,取消置 `cancelled`。
- 所有删除/取消按钮前端二次确认;数据备份靠"定期复制 `server/data/app.db`"(README 写明每周一次、换届前必备份)。

### 9.7 统计口径

- 有效报名 = `status IN ('registered','checked_in')`;已取消报名不计。
- 缺勤 = 活动已结束(`now > end_time` 且未取消)且该行 `status='registered'`。
- 单场出勤率 = 签到数 ÷ 有效报名数;平均出勤率 = 各**已结束未取消**活动出勤率的算术平均。
- 本学期定义:`8月1日—次年1月31日` 为秋季学期(起点=当年 8 月 1 日),`2月1日—7月31日` 为春季学期(起点=当年 2 月 1 日),由 `util/time.js` 的 `termStart()` 提供。
- 活跃度排行 = 本学期内 `checkin_at` 计数 Top10(按 member 分组)。
- 已取消活动不计入出勤率、月度趋势与对比图。

## 13. 风险与取舍

1. **node:sqlite 是同步 API**,会阻塞事件循环;且在部分 Node 版本标记实验性(启动有警告,可 `--no-warnings`)。几百人量级完全够用;所有"读后写"并发点必须包 `BEGIN IMMEDIATE` 事务——这是本设计最需要守住的实现纪律。
2. **JWT 无法主动吊销**:已用"中间件每请求回查 status"缓解(停用/离会立即生效);token 本体 7 天过期,localStorage 有 XSS 面——前端禁用 `v-html` 渲染用户内容、正文纯文本展示来收敛。
3. **局域网部署默认 HTTP**,密码与 token 明文传输;校园内网可接受,若迁公网必须前置反向代理加 TLS(应用代码不用改)。
4. **旋转签到码的残余风险**:防不住"在场代输",截图转发 10 分钟内仍有效;不做定位/人脸/动态二维码(对社团属过度设计),靠短窗口 + 补签留痕事后核对 + 协会制度兜底。
5. **无推送渠道**(刻意不做短信/公众号/邮件):活动取消、审核结果靠公告页 + 线下传达;后续接群机器人 webhook 只是一个 POST,不动表结构。
6. **备份靠人工**:单文件 SQLite 无自动备份,约定每周复制 `server/data/app.db`(换届前必备份);删除类操作全部二次确认 + 软删/前置条件兜底。
7. **一人一部门、角色仅三级**:跨部门任职需建两个账号或由管理员代管;不做候补队列、不做审批流(请假=开始前自助取消)。
8. **无独立报名截止字段**:截止=活动开始,需要提前收口时只能口头管理;缺勤为派生值,事后补签会回溯改变统计(接受,这正是补录的目的)。
9. **CSV 编码坑**:Excel 中文 CSV 常为 GBK,导入前端先按 UTF-8 解码、失败回退 GBK;导出统一带 BOM。
10. **Element Plus 移动端表格体验一般**:核心页面用卡片流 + 大按钮的移动优先布局规避;看板与会员管理预期主要在电脑上操作。

```sql
  activity_id INTEGER NOT NULL REFERENCES activities(id) ON DELETE CASCADE,
  category    TEXT    NOT NULL DEFAULT '其他' CHECK (category IN ('策划书','签到表','照片','总结','其他')),
  title       TEXT    NOT NULL,
  note        TEXT,
  file_path   TEXT,       -- 相对 server/data/uploads 的文件名;NULL=纯文字记录
  file_name   TEXT,       -- 用户原始文件名
  file_size   INTEGER,
  uploader_id INTEGER NOT NULL REFERENCES members(id),
  created_at  TEXT    NOT NULL
);
```
