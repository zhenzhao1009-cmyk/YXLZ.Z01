# 大学生健康协会管理系统 · 开发计划

## 1. 目标

为协会提供一个内部管理系统,把三件事搬到线上:**管人**(会员与部门)、**管事**(活动、签到与活动材料归档)、**管信息**(公告与统计)。全中文界面,电脑手机都能用,单机即可运行,预置演示数据。

明确不做:健康打卡(本次未选)、经费管理、微信小程序。

## 2. 技术架构

```
浏览器(电脑 / 手机浏览器)
   │  HTTP /api(开发时由 Vite 代理转发)
   ▼
┌──────────────────────────────┐      ┌──────────────────────────────┐
│  后端  server/                │      │  前端  web/                   │
│  Node.js 24 + Express         │◄─────│  Vue 3 + Element Plus(中文)  │
│  ├─ JWT 登录鉴权,三种角色     │ REST │  ├─ vue-router 页面路由       │
│  ├─ RESTful API              │      │  ├─ axios 统一 API 客户端     │
│  └─ node:sqlite(Node 内置)  │      │  └─ ECharts 统计图表          │
│       └─ club.db 单文件数据库  │      └──────────────────────────────┘
└──────────────────────────────┘
```

选型理由:
- **零原生依赖**:数据库用 Node 24 内置的 `node:sqlite`,密码哈希用内置 scrypt,不装任何需要编译的包。`npm install` 完直接能跑,不会在 Windows 上遇到编译报错。
- **单文件数据库**:`club.db` 一个文件就是全部数据,备份 = 复制文件。
- **两种运行方式**:开发时前后端热更新;实际使用时 `npm run build` 后由 Express 托管前端产物,一个端口跑完整系统。

安全底线:密码只存 scrypt 哈希;JWT 7 天有效期;签到码 60 秒一轮换、服务端按时间窗校验,截图与过期码无效;所有"部长可用"的接口在后端校验资源归属,防止越权。

## 3. 功能与页面规划(按角色)

### 通用(所有角色)

| 页面 | 说明 |
|---|---|
| 登录 / 注册 | 学号 + 密码登录;自助注册后待干部审核,通过方可登录(纳新审核流) |
| 公告列表 / 详情 | 置顶优先,时间倒序 |
| 活动大厅 | 按"报名中 / 进行中 / 已结束"筛选,一键报名 / 取消;活动详情页可查看与下载活动材料 |
| 我的 | 个人资料、我报名的活动、出勤记录 |
| 扫码签到页(手机) | 扫活动二维码直达,登录后一键签到,大字号确认结果 |

### 部长(管理本部门 + 活动执行)

| 页面 | 说明 |
|---|---|
| 本部门会员 | 查看与备注本部门会员 |
| 活动管理 | 发布 / 编辑自己发起的活动,查看报名名单,上传活动材料 |
| 现场签到(投屏页) | 大屏展示动态二维码(每 60 秒自动刷新,防截图代签)+ 6 位数字码兜底;实时已签到列表与计数;为特殊情况会员手工补签 |

### 管理层(会长、指导老师)

| 页面 | 说明 |
|---|---|
| 部门管理 | 部门增删改、任命部长 |
| 会员管理 | 全量会员、搜索筛选、调整部门、冻结解冻、重置密码 |
| 活动管理 | **发布** / 编辑 / 管理全部活动;上传活动材料 |
| 公告管理 | 发布 / 编辑 / 置顶 / 删除 |
| 统计看板 | 会员规模与增长、部门人数分布(饼图)、活动参与率趋势(折线图)、活跃会员排行 |

### 超级管理员

拥有管理层全部权限,另加:

| 页面 | 说明 |
|---|---|
| 账号与角色管理 | 任命会长 / 指导老师 / 部长,为管理层创建账号,删除数据 |

## 4. 数据库设计(7 张核心表)

| 表 | 用途 | 关键约束 |
|---|---|---|
| departments | 部门 | — |
| members | 会员(即账号) | 学号唯一;角色 super_admin(超级管理员)/ president(会长)/ advisor(指导老师)/ minister(部长)/ member(会员);状态 正常 / 冻结 |
| activities | 活动 | 状态由时间实时推导(即将开始 / 进行中 / 已结束)+ 取消软标记;容量(0=不限);发布人 |
| activity_signups | 报名 + 签到(单表状态流转) | 部分唯一索引防重复报名,取消后可重报;补签记录操作人留痕 |
| activity_materials | 活动材料归档 | 类别(策划书 / 签到表 / 照片 / 总结 / 其他)、标题、说明、可选附件;附件存 server/data/uploads/,记录上传人 |
| announcements | 公告 | 置顶、"需确认"标记、软删、发布人 |
| announcement_reads | 公告已读回执 | 需确认公告点"我已知晓"落回执,干部可查未读名单催办 |

字段明细、索引与建表 SQL 以 `docs/设计规范.md`(设计工作流产出)为唯一事实来源。

## 5. 关键流程规则

**报名**:活动处于"报名中"且未满员才能报名;数据库唯一约束兜底防并发重复;取消报名立即释放名额;未报名的会员现场凭码签到时自动补一条报名记录,保证出勤统计口径完整。

**签到(现场扫码,防代签)**:签到窗口自动生效(活动开始前 30 分钟至活动结束,无需手动开关);部长打开活动详情点"全屏投屏"→ 屏幕显示动态二维码(内容为 `http://<局域网IP>:3000/checkin/<活动ID>?code=XXXXXX`,每 60 秒自动刷新,截图最多 2 分钟失效)→ 会员手机扫码直达签到页,登录后一键签到 → 同时展示 6 位数字码兜底(扫码不畅时手动输入)→ 干部可手工补签 / 撤销(留痕)。签到码由服务端按时间窗(HMAC)计算,前端无法伪造。

**权限**:超级管理员 > 管理层(会长、指导老师,权限相同)> 部长 > 会员。会长、指导老师、部长等角色只能由超级管理员任命;**会长(管理层)与部长都可以发布活动**——管理层管理全部活动,部长管理自己发起的活动;部长的一切管理操作在后端限定本部门数据范围内;普通会员只能报名、签到、浏览。种子数据里为每个角色各预置一个演示账号。

**活动材料归档**:每场活动可归档多条材料记录——类别(策划书 / 签到表 / 照片 / 总结 / 其他)+ 标题 + 文字说明 + 可选附件文件(上传到服务器 uploads 目录,数据库记录文件信息与上传人)。管理层可为本部门全部活动上传,部长可为自己发起的活动上传;所有登录成员可查看与下载,方便留存协会档案。

**局域网要求**:现场签到时手机须与运行系统的电脑连同一 Wi-Fi;系统以生产模式运行(监听 0.0.0.0),二维码自动使用电脑的局域网地址,README 中会写明操作步骤。

## 6. 目录结构

```
大学生健康协会软件/
├─ server/              后端
│  ├─ index.js          入口:Express 装配、静态托管
│  ├─ db.js             建库建表 + 种子数据

├─ web/                 前端

│  ├─ src/router/       路由与登录守卫
│  ├─ src/layout/       整体布局(侧边栏 / 顶栏)
│  └─ src/views/        各页面(按模块分组)
├─ docs/                设计规范.md、开发计划.md
└─ README.md            安装与运行说明
```

## 8. 质量保障

- **照规范实现**:所有实现代理以 docs/设计规范.md 为唯一事实来源,避免各写各的对不上。
- **真实联调**:不是"应该能跑",而是启动服务逐个接口实测。
- **对抗式评审**:四个维度并行审查代码,每个发现交给独立的"怀疑者"代理验证,只有被确认的问题才修复,避免误报引起无谓改动。

## 9. 交付与运行

交付后,日常使用两种方式:

开发 / 调试:
```
node server/index.js          # 后端(首次启动自动建库 + 写入演示数据)
cd web && npm run dev         # 前端热更新,浏览器开 http://localhost:5173
```

实际使用:
```
cd web && npm run build       # 构建前端
node server/index.js          # 一个端口托管全部,浏览器开 http://localhost:3000
```

默认管理员账号与演示数据在 README 中写明。
